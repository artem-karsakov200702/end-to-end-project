# Week 14 LLM Usage Report

## Какие задачи решались с помощью LLM

На 14 неделе LLM использовался в двух ролях: как помощник в разработке шага report и как сам объект этого шага — он встроен в проект как отдельный модуль, пересказывающий агрегаты витрины с автоматической проверкой на галлюцинации.

С помощью LLM были выполнены:

- подготовка кода скрипта `src/llm/llm_summary.py`;
- проектирование JSON-контекста для модели (метрики, аномалии, constraints);
- формулировка system и user prompt с запретом выдумывать числа;
- подготовка регулярок и валидатора `validate_numbers()`;
- подготовка `.env.example`;

## Что сделано самостоятельно

- настройка `.env`, регистрация в OpenRouter, ротация ключа;
- запуск скрипта и итеративная отладка реальных ошибок:
  - `403 unsupported_country` — переход с OpenAI на OpenRouter, добавление `OPENAI_BASE_URL`;
  - `401 invalid_api_key` — фикс `OPENAI_MODEL` на `openai/gpt-4o-mini`;
  - FAIL валидатора на `-03`, `-06` — оказались фрагментами дат, поправлена регулярка;
  - FAIL валидатора на `-3` — оказался дефисом из «Топ-3», поправлен lookbehind;
  - пустые `metrics: []` — переписан автодетект колонок под реальный mart (`temp_mean_c`, `precip_sum_mm` и т.д.);
- ручная проверка `summary.md` и `context_used.json` — числа в сводке совпадают с контекстом;

## Вывод

LLM ускорил разработку, но архитектура и отладка — самостоятельные. Главный принцип недели: **числа считает Python, LLM только пересказывает, а валидатор сверяет каждое число с контекстом**. Строки FAIL и PASS в логе подтверждают, что защита от галлюцинаций работает на практике.
